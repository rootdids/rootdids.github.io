# Dids-Hen — multi-fw auto-install bundle

Hooks `Settings > System > Information` on PS4 under HEN and swaps the
**SouthBridge** field (vanilla `Aeolia A2` on the confirmed console) to
`Dids ❤️`.

Supports every firmware where GoldHEN runs: **5.05 and 7.00 through 13.52**.
14.00 is not covered because no public jailbreak exists for that fw.

## The flow (zero touches after the first visit per console)

1. **Fork this repo** to your GitHub account.
2. In the fork's settings → **Pages**, pick **main branch / root** as the
   source. GitHub serves the site at `https://<your-user>.github.io/<repo>/`.
3. Push once — the included **GitHub Actions workflow** (`.github/workflows/build.yml`)
   compiles both artifacts automatically:
   - `plugin/dist/Dids-Hen.prx` — the plugin (SouthBridge rename)
   - `plugin/dist/dids_installer.bin` — the one-shot payload that writes
     the plugin to disk + wires `plugins.ini` auto-load
   The Action commits them back under `plugin/dist/`, so GitHub Pages
   serves them straight away. No local toolchain required.
4. On each PS4 (9.00 → 13.52), open the browser and hit your Pages URL.
   The site routes to the right chain for the console's firmware
   automatically. HEN loads, the installer runs **once**, writes
   `Dids-Hen.prx` + the `plugins.ini` entry.
5. From the **next HEN boot** onward: GoldHEN sees the plugin in
   `plugins.ini` under `[default]` and fires it automatically every
   boot. SouthBridge shows `Dids ❤️` on every console with no further
   interaction.

The installer is **idempotent** — rerunning it (re-visiting the site)
checks what is on disk already and no-ops if the plugin is in place and
the `plugins.ini` line is present. Safe to run on every visit.

| fw range       | chain entry file               |
|----------------|--------------------------------|

## Wiring the installer into each chain (one line per chain)

Every chain's final step calls its own payload sender (varies by chain:
`send_payload`, `load_bin`, `pivot_run`, etc.) with `goldhen.bin` as the
argument. Right after that call, append:

```js
if (window.DIDS_INSTALL === true && window.DIDS_INSTALL_BIN) {
  try { window.didsLoadInstaller(<sendPayloadFunction>); } catch (e) {}
}
```

Where `<sendPayloadFunction>` is the chain's own sender (the function
that fetches a URL and feeds its bytes to the exploit's payload stage).

Example for `g2all/slopkit/jb.js` (13.02 – 13.52), the pattern is:

```js
// ... goldhen.bin load code already here ...
send_bin("../../goldhen.bin");
// NEW: auto-install Dids-Hen plugin
if (window.DIDS_INSTALL === true) {
  try { window.didsLoadInstaller(send_bin); } catch (e) {}
}
```

Each chain is one line. The `install.js` already exposes
`window.didsLoadInstaller` and the URL to fetch, so the chain code just
calls it. If the chain's sender takes a URL that's root-relative, the
`install.js`-set `DIDS_INSTALL_BIN` is `plugin/dist/dids_installer.bin`.

**NOTE**: these chain modifications were not applied automatically in
this build to avoid the risk of regressing a chain I can't test on
hardware. The `install.js` kicker is wired into every landing (so the
flag is live). The one-line chain hook is yours to paste in once per
chain. Or ask me to do them chain-by-chain once you've verified 13.52
works.

## If you want to install manually (no chain mod, no CI)

If you'd rather skip the chain-mod step entirely, the manual install is:

1. Download `plugin/dist/Dids-Hen.prx` from your repo (built by CI).
2. FTP it to `/data/GoldHEN/plugins/Dids-Hen.prx` on the console.
3. Add this line to `/data/GoldHEN/plugins.ini` under `[default]`:

   ```
   [default]
   /data/GoldHEN/plugins/Dids-Hen.prx
   ```

4. Reboot. HEN auto-loads it from then on.

## Fallback / neutralization notes

- UTF-8 heart `❤️` is 6 bytes (red heart + VS16). If the on-screen
  buffer trims the VS16, drop the trailing `EF B8 8F` from `DIDS_STR`
  in `source/main.c` to fall back to the plain `❤`.
- The plugin sniffer matches `Aeolia`, `Belize`, `Baikal`, or `CXD`
  prefixes on the SouthBridge field. If your console shows a different
  chip name (older or newer SKU), add that prefix to `sb_match`'s
  memcmp list in `source/main.c`.
- To temporarily disable the plugin without deleting it, comment out
  its line in `plugins.ini` by prefixing with `;`.
